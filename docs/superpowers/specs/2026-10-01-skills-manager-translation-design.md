## 1. 背景与目标

子项目甲让用户"看得见"插件技能（156 条）、官方技能（19 条）与各自元数据，但这些内容全是英文——技能名与说明的原文来自各技能自带的 `SKILL.md`。用户要求：**双语标题 + 一键翻译 + 简单中文解释**。

本子项目目标：在软件内加一个「一键翻译」：点一下，把只读内容的中文译名与中文一句话说明批量生成并**缓存在软件自己这里**（永不写进插件目录），此后永久有效；插件升级后只补翻变化的部分。

## 2. 范围

**做**：
- 翻译对象：插件技能（名 + 说明）、官方技能（名 + 说明）、插件分组说明
- 界面呈现：**英文原名保持为主**，其下显示中文译名与中文一句话说明；详情面板顶部显示中文说明，英文原文仍在正文
- 手动触发：块头「一键翻译」按钮 + 「N 条待翻译」提示；未配置接口时按钮变「去设置翻译接口」
- 接口设置：地址 / 模型 / 格式（Anthropic 或 OpenAI 兼容）/ 密钥（系统钥匙串）；默认预填本机网关 `http://127.0.0.1:8789`（Anthropic 格式，密钥见 `D:\CloudMusic\workbuddy-anthropic-gateway\data\api-key.txt`）；提供「测试连接」
- 缓存：新表按「内容指纹」记账；内容未变永不重翻；变了自动视为待翻
- 幂等与续跑：中途退出后再次点击，从剩余条目继续

**不做**（留给后续）：
- MCP 接入（让智能体读取/控制本软件）
- 自动翻译（只有点按钮才调用接口）
- 实时进度条（仅显示「翻译中…（第 X/Y 批）」，完成后一次刷新）
- 个人技能（`个人` 档）的翻译

## 3. 验收标准

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 接口配置 | 设置页可填 地址/模型/格式/密钥；「测试连接」成功打勾，失败给出可读原因；密钥不落明文（钥匙串） |
| 2 | 一键翻译 | 插件页点按钮后，技能行出现中文译名 + 中文说明；插件分组说明出现中文；「N 条待翻译」归 0 |
| 3 | 不重复花钱 | 翻译完成后再次点击 → 提示「没有需要翻译的」 |
| 4 | 增量 | 插件升级/新装后 → 提示「有 N 条待翻译」，点击只翻新增/变化条目 |
| 5 | 持久 | 重启软件后中文仍在（已落库） |
| 6 | 只读铁律 | `plugins/` 目录零写入；插件技能仍无编辑/删除/同步入口 |
| 7 | 不弄坏老功能 | 甲的全部功能与既有功能照常 |

## 4. 技术设计

### 4.1 组件

| 组件 | 位置 | 职责 |
|---|---|---|
| 机翻缓存表 | `src-tauri/src/core/translation_store.rs` + `core/migrations.rs` 加迁移 | 表 `skill_translations(fingerprint TEXT PRIMARY KEY, kind TEXT, source_name TEXT, zh_name TEXT, zh_description TEXT, model TEXT, created_at TEXT)`；提供读取/写入/统计 |
| 翻译引擎 | `src-tauri/src/core/translator.rs` | 批量（每批 20 条）组装请求、调用接口、容错解析、失败重试一次、整批成功才落库 |
| 命令层 | `src-tauri/src/commands/translation.rs` | `get_translation_settings` / `set_translation_settings` / `test_translation_connection` / `get_translation_status` / `translate_skills` / `clear_translations` |
| 前端组件 | `src/components/PluginSkillsSection.tsx`（改） | 双语渲染、按钮与计数、未配置时的跳转、翻译中状态、结果汇总提示 |
| 前端设置 | `src/views/Settings.tsx`（改） | 「AI 翻译」小节（字段 + 测试连接） |
| 前端 API/文案 | `src/lib/tauri.ts`、`src/i18n/{en,zh,zh-TW}.json` | 类型与封装；新增文案三语齐全 |

### 4.2 数据流

1. 前端取「当前只读条目集合」（复用甲的 `get_claude_plugin_skills` 返回的 `groups`/`official`，插件分组说明取 `plugin.json` 的 `description`）。
2. 后端为每条计算**指纹** = `sha256(kind + 原名 + 英文说明)`（复用 `core/content_hash`）。
3. 指纹不在缓存者 = 待翻译集合 → 按 20 条分批。
4. 每批：组装提示词 → 调接口（按格式构造）→ 解析 JSON 数组 → 校验条数/字段 → **整批写入**缓存。
5. 返回汇总 `{ translated, failed, pending }`；前端刷新。

### 4.3 接口与密钥

- 格式二选一：`anthropic`（`POST {endpoint}/v1/messages`，`x-api-key`）或 `openai`（`POST {endpoint}/v1/chat/completions`，`Authorization: Bearer`）
- 密钥存系统钥匙串（沿用现有 `keyring` 用法）；地址/模型/格式存现有 settings 表
- 默认预填 `http://127.0.0.1:8789` + 格式 `anthropic`（用户本机网关）；**模型名默认留空**，在设置页提示"填入你网关支持的模型名"，未填时「测试连接」直接给出明确提示
- 模型只返回部分条目时：已返回且校验通过的写入缓存，未返回的留待下次点击（不视为失败）

### 4.4 出错处理（逐条明确）

| 情况 | 行为 |
|---|---|
| 未配置 | 命令返回明确错误；界面按钮显示「去设置翻译接口」并跳转设置页 |
| 网络/鉴权/限流 | 该批记失败并继续下一批；汇总「成功 X / 失败 Y（再点只重试失败的）」 |
| 模型输出格式坏 | 该批自动重试一次；仍坏 → 整批不写入（禁止半条脏数据） |
| 中途退出 | 已完成批次已落库；下次从剩余继续（按指纹幂等） |

### 4.5 测试计划

自动（Rust 单测，全部离线，用可注入的假后端）：

1. 指纹：同内容稳定；说明变化 → 指纹变化
2. 分批：195 条 → 10 批（20 条/批）
3. 解析容错：裸 JSON、```json 围栏、前后混文字、字段缺失（缺项跳过而非整批失败）
4. 请求构造：两种格式的 URL/headers/body 形状断言
5. 失败不落库：整批失败 → 缓存表零新增；重试路径按指纹重取剩余
6. 统计：待翻译计数 = 扫描集合 − 缓存命中

手工验收：规格书第 3 节 7 行表（用户执行）。

## 5. 风险与退路

| 风险 | 应对 |
|---|---|
| 本机网关不可用/换机 | 设置页可改地址与格式；「测试连接」先验证再翻译 |
| 模型输出不稳定 | 整批重试一次 + 整批原子写入；失败不污染缓存 |
| 翻译质量 | 界面上英文原文始终可见（中文只是补充）；可「清缓存重翻」 |
| 花费失控 | 仅手动触发；按指纹去重；再点不重复调用 |
| 弄坏甲的功能 | 只加不改：设置的读写、缓存表、组件内渲染均为新增；甲的既有测试必须保持全绿 |
